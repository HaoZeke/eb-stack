#+TITLE: Dependency closure
#+OPTIONS: toc:t num:nil author:nil

A dependency closure lists every module one change reaches. The change
may be an easyconfig, an easyblock, or one bundled component. A software
bill of materials (SBOM) records the components and the edges. The record
is planned: the recipes supply it before anything is installed.

An easyconfig author reads the closure of one recipe bump. A reviewer
compares pull requests that share a file or a module. An easyblock author
lists the recipes that name a changed class. A framework author lists
those recipes. Triage lists the installed modules that carry one component
from a Common Vulnerabilities and Exposures (CVE) entry. A software-layer
maintainer lists the pull requests that would build one module. A site maintainer lists the
installed modules an upstream pull request changes. The annual toolchain
bump is the generation step in the first section. A security or compliance
reader consumes the CycloneDX document. A conda-forge porter reads the
planned SBOM from ~package inspect~. A Spack porter reads that document
too.

Those questions show up for the European Environment for Scientific
Software Installations (EESSI). Other stacks raise them too. These fixture
trees supply the inputs. The inputs include
under ~tests/~. That examples directory contains the checksum recipe, both
pull-request files, the curl recipes, the easyblock tree, ~Tool-1.0.eb~,
the site installed list, and the package-plan policy. Each command takes
an easyconfigs tree and, where the question is a mounted prefix, a list
of installed modules. The runs write under ~/tmp/sbom-demo~.

* The annual toolchain bump

A generation maintainer asks which packages change version together.
The step is foss-2025a to foss-2025b. The same question covers the build
list and the Jenkins root.
~stack solve --sbom-out~ writes a CycloneDX 1.5 document for the selection.
~stack sbom --lock~ writes the same document later, from the lock. Both
commands read edges and checksums from the easyconfigs the lock names. A
runtime dependency that is also selected is a ~dependsOn~ edge. A
builddependency is the component property ~eb_stack:buildDependsOn~. An
unreadable path
contributes no edge. The document does not draw an edge from every package
to every other package.

The fixture ~fixtures/gromacs_2025_to_next~ is that step.
~--build-list-out~ writes the easyconfigs to build.
~--jenkins-roots-only~ writes one Jenkins line for each policy root and
leaves the dependencies to ~eb --robot~.

#+begin_src bash
eb-stack stack solve \
  --easyconfigs fixtures/gromacs_2025_to_next/easyconfigs \
  --policy fixtures/gromacs_2025_to_next/policies/prefer_newer.json \
  --baseline-easyconfigs fixtures/gromacs_2025_to_next/easyconfigs \
  --lock-out /tmp/sbom-demo/stack.lock.json \
  --sbom-out /tmp/sbom-demo/stack.cdx.json \
  --stack-diff-out /tmp/sbom-demo/stack.diff.md \
  --build-list-out /tmp/sbom-demo/build.list \
  --jenkins-build-list-out /tmp/sbom-demo/jenkins.list \

* A checksum dict when the version changes

The hash in that SBOM has to name the artifact the new version will fetch.
A version bump with no new checksum clears the old digest to an empty
string and records a residual. It does not keep the previous tarball's
hash. The input recipe assigns ~local_arch~ from ~ARCH~. The map sends
~x86_64~ to ~linux-amd64~ and ~aarch64~ to ~linux-arm64~. ~sources~ uses
that name, and the checksum dict uses it too. ~notes.txt~ is absent.
~easyblock~ is ~ConfigureMake~.
