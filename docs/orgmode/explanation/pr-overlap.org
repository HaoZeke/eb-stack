#+TITLE: From one easystack line to a build set
#+OPTIONS: toc:t num:nil author:nil

~eb-stack pr-overlap~ turns each easystack line a pull request adds into the
modules that line would build on the installed stack. This page follows open
EESSI software-layer pull requests 1728 and 1787 for 2026.06, against
~/cvmfs/software.eessi.io~ ~x86_64/amd/zen4~, using the easyconfigs that come
with EasyBuild 5.4.0. The zen4 run loaded ~EESSI-extend~ and passed that
module's ~EASYBUILD_FILTER_DEPS~, the ~modules/all~ tree, and the EasyBuild
5.4.0 easyblocks package. The command writes records. It does not build.

The commands that produce the same files are in
[[file:../howto/pr-overlap.org][find shared builds across open pull requests]].
The record fields are in [[file:../reference/formats.org][output formats]].

the walk records these three dependencies and does not open them. The module

* Merge order and knock-on

1. Edge A -> B when a module in B's ~to_build~ is an easystack entry A adds
   (A asks for it by name; B only reaches it). Edges both ways form a cycle.
2. Among pull requests with no remaining incoming edge, pick the one whose
   residual build set is smallest, then the lowest pull request number.
3. After picking, add its residual builds to the installed set and recompute
   residuals for the rest. ~saves~ is that difference.
4. A strongly connected component is reported in ~cycles~. Edges inside it
   are dropped, and rule 2 orders its pull requests with every other pull
   request that has no remaining incoming edge.

The module an entry asks for is the easyconfig filename with the package
name and the rest split by ~/~, the same ~name/version[-toolchain]versionsuffix~
string ~to_build~ uses. ~Lib-1.0-GCCcore-15.2.0.eb~ asks for
~Lib/1.0-GCCcore-15.2.0~.

~--merged~ numbers are not steps. Their ~to_build~ modules count as
installed before rule 2 runs. A number that is not in the ~--pr~ input is
an error, and the message names that number.

For each easystack path changed by 2 or more pull requests, the insertion
point is the 0-based index of the base line before the first added line,
from a line LCS of base and head. The point is -1 when the added lines
start at the top of the file. The same point is ~same-insertion~. Identical
added lines are ~same-entry~.
