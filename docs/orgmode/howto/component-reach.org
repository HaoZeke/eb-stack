#+TITLE: Which modules carry a component, and what that forces rebuilt
#+OPTIONS: toc:t num:nil author:nil

Goal: a CVE names a component and a version. List every easyconfig and
installed module in one toolchain generation that carries it, then feed
the recipes that contain it into the rebuild closure.

* Run it

#+begin_src bash
eb-stack component-reach \
  --component curl \
  --version '>=8,<9' \
  --generation 2026.1 \
  --easyconfigs /path/to/easybuild/easyconfigs \
  --installed installed.txt \
  --easystack easystacks/software.eessi.io/2026.06/*.yml \
  --compat-layer compat.txt \
  --filter-deps "$EASYBUILD_FILTER_DEPS" \
  --out-dir out/
#+end_src

~--component~ is the name. ASCII case is ignored, so ~curl~ matches
~cURL~ and ~jupyterlab~ matches ~JupyterLab~. The match is a whole token,
so ~jupyterlab~ does not match ~jupyterlab-server~ and ~curl~ does not
match ~libcurl~.

~--version~ is an exact version, ~*~ for any version, or a requirement
such as ~>=8,<9~. ~--generation~ is the toolchain generation, for example
~2026.1~. A recipe is in that generation when its toolchain version is
that string, or when its toolchain is a member of the known foss
hierarchy for that generation. ~GCCcore-15.2.0~ and ~GCC-15.2.0~ belong
to ~2026.1~. A system toolchain does not. A module built with another
generation is not a row.

* What carries it

- the easyconfig's own module name and version;
- a ~dependencies~ or ~builddependencies~ tuple;
- a bundle ~components~ entry;
- a Python, R, or Perl extension in ~exts_list~;
- a Cargo crate, from a ~crates~ tuple or from a filename such as
  ~libz-sys-1.1.29.tar.gz~, including a vendored ~+name-version~ fragment
  such as ~0.4.89+curl-8.20.0~;
- a vendored or bundled filename in ~sources~ or ~patches~ whose name
  contains the component and a version;
- a line in ~--compat-layer~, ~name version~ or ~name==version~, ~#~
  comments skipped.

A dependency or a builddependency lists the recipe as a carrier and does
not add it to the patched set. The component's own module is the root,
and those recipes are its closure. A module, bundle component, extension,
crate, source, or patch means the recipe contains the bytes, and that
filename is a patched root.

The compat layer is not an easyconfig. Pass it with ~--compat-layer~. A
hit is a row with an empty easyconfig and a note that it has no rebuild
edge.

~--filter-deps~ drops dependency tuples before the closure walk, the same
way as ~rebuild-set~, and does not strip ~exts_list~. When the flag is
omitted and ~EASYBUILD_FILTER_DEPS~ is set, the command reads it.

* The closure

With no ~--easystack~, every easyconfig in the generation is the stack.
With no ~--installed~, every module in the generation is treated as
installed, so the reverse walk does not stop. Pass both when the question
is a mounted prefix: then only those modules are visited.

The closure is the rebuild set of the containing recipes, inside the
generation. Classes are the same as ~rebuild-set~: ~must-rebuild~,
~review~, and ~no-rebuild~. This command does not read a prefix or scan
static symbols.

* Read the three files

~out/component-reach.md~ is the carrier table and the closure table.
~out/component-reach.json~ is the same document.
~out/component-reach.toml~ starts with
~# Generated by `eb-stack component-reach`.~
