#+TITLE: From-commit pins already in an EasyBuild release
#+OPTIONS: toc:t num:nil author:nil

An easystack ~from-commit~ pin asks EasyBuild to take an easyconfig from
that commit of easybuild-easyconfigs. Pin it when the file is newer than
the EasyBuild release the stack builds with. A pin whose commit is already
in that release does nothing. Removing it is safe only when the easyconfig
at the pin is the same blob as at the release tag. A later edit, such as
the glibc 2.43 patch on UCX 1.18.0 and 1.19.0, means the release file is
not the pinned file, and a person has to decide.

* Check the easystacks

~--easybuild-version 5.4.0~ names the release. When the flag is omitted,
the command reads ~eb-X.Y.Z~ from the file name
(~20261011-eb-5.4.0-UCX.yml~). The flag overrides the file name. With
neither, the command exits 2 and names ~--easybuild-version~.

#+begin_src bash
eb-stack stack from-commit \
  --easystack 20261011-eb-5.4.0-UCX.yml \
  --easyconfigs-repo "$EB_EASYCONFIGS" \
  --easyblocks-repo "$EB_EASYBLOCKS"
#+end_src

~--easyconfigs-repo~ is an easybuild-easyconfigs checkout, tags included.
~--easyblocks-repo~ is the easybuild-easyblocks checkout, and it is required
only when an entry sets ~include-easyblocks-from-commit~. The tags are
~easybuild-easyconfigs-vX.Y.Z~ and ~easybuild-easyblocks-vX.Y.Z~.

Each pin is one line:

#+begin_example
status=released blob=differs version=5.4.0 tag=easybuild-easyconfigs-v5.4.0 kind=from-commit commit=d438adc file=UCX-1.18.0-GCCcore-14.2.0.eb easystack=20261011-eb-5.4.0-UCX.yml
pins=1 released=1 newer=0 unknown=0
#+end_example

~released~ means ~git merge-base --is-ancestor~ says the commit is in the
tag. ~newer~ means the commit is in the checkout and is not in the tag.
~unknown~ means the commit or the tag is missing. The command does not
guess which. ~reason=commit-missing~ or ~reason=tag-missing~ says which
one.

For a ~released~ ~from-commit~ pin, ~blob~ compares the easyconfig blob in
the tree at the pin with the blob at the tag. ~same~ means one object.
~differs~ means the path is missing on one side, the hashes differ, or
more than one path has that filename. ~released~ and ~same~ can be
removed. ~released~ and ~differs~ needs a person.

An ~include-easyblocks-from-commit~ pin has no single easyconfig in that
repository. ~blob~ there compares the tree of the pin with the tree of
~easybuild-easyblocks-vX.Y.Z~. ~same~ means the release tree is the pinned
tree.

The command exits 0 when no pin is ~released~. It exits 1 when any pin is
~released~, including a pin whose blob is ~same~. ~--json~ prints the same
fields as JSON. ~eb_stack_from_commit~ returns that report.
