#+TITLE: Bump an existing EasyBuild recipe
#+OPTIONS: toc:t num:nil

A bump is a canonical EasyBuild-origin package bundle. It emits a planned
SBOM, a Resolvo lock, and a rewritten recipe; it does not use a separate text
rewrite API.

* Retarget the toolchain generation

#+begin_src bash
eb-stack package bump \
  --source tests/repro_fixtures/gromacs/GROMACS-2024.4-foss-2023b.eb \
  --toolchain-name foss \
  --toolchain-version 2024a \
  --easyconfigs tests/repro_fixtures/universe_foss_2024a \
  --out-dir /tmp/eb-stack/bundles/gromacs-2024a
#+end_src

The solver materializes the source recipe as a default profile, derives the
target toolchain hierarchy from the robot tree, and asks Resolvo for a jointly
feasible dependency selection. Existing robot artifacts keep independent
build-tool scopes, matching EasyBuild's installed-module model.

The output is:

#+begin_src text
/tmp/eb-stack/bundles/gromacs-2024a/
  package.plan.json
  package.sbom.cdx.json
  locks/default.lock.json
  easyconfigs/g/GROMACS/GROMACS-2024.4-foss-2024a.eb
#+end_src

* Use site overlays and stack preferences

Pass robot paths from general to specific. An explicit override is a
locked solver input. This fixture's universe already selects Python
3.12.3, and ~--dep~ records that pin:

#+begin_src bash
eb-stack package bump \
  --source tests/repro_fixtures/gromacs/GROMACS-2024.4-foss-2023b.eb \
  --toolchain-name foss \
  --toolchain-version 2024a \
  --easyconfigs tests/repro_fixtures/universe_foss_2024a \
  --dep Python=3.12.3 \
  --out-dir /tmp/eb-stack/bundles/gromacs-dep
#+end_src

Preferred distribution pins participate in the SAT solve and may fall back.
Locked pins are exact constraints. Both outcomes are recorded in the profile
lock, so a site preference never becomes an invisible post-solve edit.
When a selected pin belongs to another toolchain generation, the emitted
dependency tuple includes that toolchain explicitly. Source dependencies that
already use an explicit toolchain preserve their family and retarget its
generation before solving.

* Change the application version

#+begin_src bash
eb-stack package bump \
  --source tests/repro_fixtures/gromacs/GROMACS-2024.4-foss-2023b.eb \
  --toolchain-name foss \
  --toolchain-version 2024a \
  --version 2024.5 \
  --easyconfigs tests/repro_fixtures/universe_foss_2024a \
  --out-dir /tmp/eb-stack/bundles/gromacs-2024.5
#+end_src

The emitter updates the package version, target toolchain, selected dependency
versions, conventional filename, and source checksum entry. Patches remain
explicit review work. Omitting the new checksum clears the old digest to an
empty string and records a residual. The bump never invents a digest.

To fill the digest without a separate EasyBuild run, pass ~--fetch-checksums~.
The bump resolves ~sources~ and ~source_urls~ at the new version, downloads
each entry from those URLs in order, and writes the first source's SHA-256 into
the recipe and the SBOM, which is what ~eb --inject-checksums~ does on the
EasyBuild host. A git checkout, a missing URL or a failed download stays empty
and is listed in ~sources.fetch.json~ and as a ~source:fetch~ residual:

#+begin_src bash
eb-stack package bump \
  --source tests/repro_fixtures/gromacs/GROMACS-2024.4-foss-2023b.eb \
  --toolchain-name foss \
  --toolchain-version 2024a \
  --version 2024.5 \
  --fetch-checksums \
  --easyconfigs tests/repro_fixtures/universe_foss_2024a \
  --out-dir /tmp/eb-stack/bundles/gromacs-fetch
#+end_src

The download fills ~gromacs-2024.5.tar.gz~ in ~checksums~. The digest
written for that tarball is
~fecf06b186cddb942cfb42ee8da5f3eb2b9993e6acc0a2f18d14ac0b014424f3~.

* Check and build

#+begin_src bash
RECIPE=/tmp/eb-stack/bundles/gromacs-2024a/easyconfigs/g/GROMACS/GROMACS-2024.4-foss-2024a.eb

eb-stack recipe format "$RECIPE"
eb-stack recipe lint "$RECIPE"
eb-stack recipe check \
  --recipe "$RECIPE" \
  --easyconfigs tests/repro_fixtures/universe_foss_2024a \
  --easyconfigs /tmp/eb-stack/bundles/gromacs-2024a/easyconfigs

mkdir -p /tmp/eb-stack/robot
rsync -a tests/repro_fixtures/universe_foss_2024a/ /tmp/eb-stack/robot/

podman build -t eb-stack-rocky9 \
  -f skills/new-package/container/rocky9/Containerfile \
  skills/new-package/container/rocky9

eb-stack campaign run \
  --bundle /tmp/eb-stack/bundles/gromacs-2024a \
  --config examples/targets/local-podman.toml \
  --target local-rocky9 \
  --state /tmp/eb-stack/bundles/gromacs-2024a.campaign.json
#+end_src

~package bump~ can establish *resolves*. Only the campaign's EasyBuild run can
establish *builds*, and only declared verification commands can establish
*binary-verified*. Follow ~skills/annual-bump/SKILL.md~ for batch operation and
repair handling.
