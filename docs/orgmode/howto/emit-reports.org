#+TITLE: Emit a build list and stack diff
#+OPTIONS: toc:nil num:nil

Goal: alongside the lock, get an install-ordered build list for a
build pipeline and a markdown diff you can paste straight into a pull
request. The commands below write those files under ~/tmp~. Baseline,
closure, generation, and reachability are in
[[file:../reference/glossary.org][the glossary]].

* Add the two flags to solve

~stack solve~ accepts ~--build-list-out~ and ~--stack-diff-out~. They are
independent: pass either, both, or neither.

#+begin_src bash
eb-stack stack solve \
  --easyconfigs fixtures/gromacs_2025_to_next/easyconfigs \
  --stack-policy fixtures/gromacs_2025_to_next/policies/prefer_newer.json \
  --baseline-easyconfigs fixtures/gromacs_2025_to_next/easyconfigs \
  --lock-out /tmp/emit-stack.lock.json \
  --sbom-out /tmp/emit-stack.cdx.json \
  --build-list-out /tmp/emit-build.list \
  --stack-diff-out /tmp/emit-stack.diff.md
#+end_src

~--stack-diff-out~ needs a baseline lock. Omit ~--baseline-easyconfigs~ and
the first ~--easyconfigs~ tree is that baseline. Pass ~--baseline-easystack~
to diff against what those easystacks install. A caller that can form no
baseline fails and names ~--baseline-easyconfigs~ or ~--baseline-easystack~.
There is no ~--baseline~ flag.

To diff against what a software layer already installs, pass its easystacks as
the baseline instead of an older tree:

#+begin_src bash
eb-stack stack solve \
  --easyconfigs fixtures/gromacs_2025_to_next/easyconfigs \
  --toolchain foss/2025b --root GROMACS \
  --baseline-easystack fixtures/gromacs_2025_to_next/easystacks/gromacs-2024.4.yml \
  --build-list-out /tmp/site.list \
  --build-list-excludes-baseline \
  --stack-diff-out /tmp/easystack.diff.md \
  --lock-out /tmp/easystack.lock.json
#+end_src

The baseline label is the toolchain (~foss-2025b~), the same shape as the
solved lock. ~/tmp/site.list~ contains the version-bumped modules in build
order, and leaves out what the easystack already installs:

#+begin_src text
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/OpenBLAS-0.3.27-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/OpenMPI-5.0.3-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/GROMACS-2025.0-foss-2025b.eb
#+end_src

~/tmp/easystack.diff.md~ opens with ~Baseline (`foss-2025b`) to solved (`foss-2025b`)~.
Unchanged: 2 (FFTW, Python). Version-bumped: 3 (GROMACS 2024.4 to 2025.0,
OpenBLAS 0.3.24 to 0.3.27, OpenMPI 4.1.6 to 5.0.3).

* Read the build list

#+begin_src text
cat /tmp/emit-build.list
#+end_src

One easyconfig path per line, dependencies before the packages that need
them (a topological sort over the co-selected stack, ties broken by package
name for a deterministic order):

#+begin_src text
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/FFTW-3.3.10-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/OpenBLAS-0.3.27-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/OpenMPI-5.0.3-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/Python-3.12.3-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/GROMACS-2025.0-foss-2025b.eb
#+end_src

Feed this straight into a sequential build pipeline: ~xargs -n1 eb build~,
a Jenkins matrix step, or a plain shell loop.

* Read the stack diff

Every co-selected package is classified against the baseline lock as
~unchanged~, ~added~, ~removed~, or ~version-bumped~:

#+begin_src markdown
# Stack diff

Baseline (`foss-2025a`) to solved (`foss-2025b`).

## Summary

- **unchanged**: 2
- **added**: 0
- **removed**: 0
- **version-bumped**: 3

## Packages

### FFTW: unchanged

- Baseline: `3.3.10` (`fixtures/gromacs_2025_to_next/easyconfigs/foss-2025a/FFTW-3.3.10-foss-2025a.eb`)
- Solved: `3.3.10` (`fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/FFTW-3.3.10-foss-2025b.eb`)

### GROMACS: version-bumped

### OpenBLAS: version-bumped

#+end_src

A tree baseline and an easystack baseline are both labelled with the
toolchain (`foss-2025a`, `foss-2025b`). Paste the file
body directly into a pull request description; every line names a real
version and a real easyconfig path.

* Plan a site layer on EESSI 2026.06

The fixture above is one root and one small easystack. A site layer on
European Environment for Scientific Software Installations (EESSI)
2026.06 uses the same flags against the trees
~scripts/fetch-upstream-trees.sh~ checks out. Source the ~env.sh~ it
writes. ~--toolchain foss/2026.1~ is the generation named by
~eessi-2026.06-eb-5.4.0-2026.1.yml~. Pass ~--baseline-commits-from~ the
clone root (~git rev-parse --show-toplevel~ from ~$EB_EASYCONFIGS~).
~env.sh~ sets ~EB_EASYCONFIGS~ to the ~easybuild/easyconfigs~ directory,
and that value is not the git root.

There is no ~GROMACS-*-foss-2026.1.eb~ in the pinned develop tree. The
newest foss GROMACS file there is ~GROMACS-2026.2-foss-2025b.eb~. This
exits 1, and the error contains ~no candidates for root package GROMACS~:

#+begin_src bash
eb-stack stack solve \
  --easyconfigs "$EB_EASYCONFIGS" \
  --toolchain foss/2026.1 \
  --root GROMACS \
  --baseline-easystack "$EB_EESSI_SOFTWARE_LAYER/easystacks/software.eessi.io/2026.06/eessi-2026.06-eb-5.4.0-2026.1.yml" \
  --baseline-commits-from "$(git -C "$EB_EASYCONFIGS" rev-parse --show-toplevel)" \
  --build-list-excludes-baseline \
  --lock-out /tmp/site-gromacs.lock.json \
  --build-list-out /tmp/site-gromacs.list \
  --stack-diff-out /tmp/site-gromacs.diff.md
#+end_src

On failure the same message appends dependencies the filtered universe
does not provide (for example ~impi~ and ~imkl-FFTW~). That list is the
whole searched tree, not the root's own dependencies.

A root that does exist, and that this easystack does not install, is
PuLP. The same command with ~--root PuLP~ and ~--lock-out
/tmp/site-pulp.lock.json~ prints:

#+begin_example
lock=/tmp/site-pulp.lock.json packages=59
#+end_example

~--build-list-excludes-baseline~ leaves one line, ending in
~PuLP-3.3.2-foss-2026.1.eb~. The diff summary is unchanged 58, added 1,
removed 272. ~removed~ is the rest of the baseline this one-root solve
does not select. It is not a list of modules to uninstall. ~arpack-ng~
is already in that baseline closure, so the same command writes an
empty build list and ~added: 0~.

~stack oom --arch x86_64/amd/zen4~ on that easystack, with
~--easyconfigs "$EB_EASYCONFIGS"~, prints ~oom=0 fits=0 builds=339
nodes=2~. ~fits=0~ means no build had a row in the memory table. The
warning example is the fixture in
[[file:oom-profile.org][warn before a job runs out of memory]].

The other checks for this layer, without a mounted prefix:

- ~stack from-commit~ on the 2026.06 easystack, with ~--easyconfigs-repo~
  set to the clone root. The file name selects EasyBuild 5.4.0. On this
  pin the count line is ~pins=20 released=0 newer=20 unknown=0~ and the
  process exits 0. See
  [[file:from-commit-released.org][find from-commit pins an EasyBuild release already contains]].
- ~rebuild-set --findings~ on the recorded findings file. See
  [[file:rebuild-set.org][what an in-place patch forces EESSI to rebuild]].
- ~component-reach --cve~. The manual does not name an id. A record whose
  only range is a git range (~CVE-2025-66471~, urllib3, generation
  ~2026.1~, this pin) prints ~carriers=0~ and ~review=1~, and the
  markdown says ~GIT range not parsed~. See
  [[file:component-reach.org][which modules carry a component]].
- ~pr-overlap~ on ~tests/pr_overlap_layer~. The mounted-stack block needs
  the EESSI init script under ~/cvmfs/software.eessi.io~. See
  [[file:pr-overlap.org][find shared builds across open pull requests]].
- ~eb-stack mcp --help~ exits 0. One JSON-RPC ~initialize~ on stdin
  returns server name ~eb-stack~. See
  [[file:../reference/mcp.org][the Model Context Protocol server]].
