#+TITLE: Emit a build list and stack diff
#+OPTIONS: toc:nil num:nil

Goal: alongside the lock, get an install-ordered build list for a
build pipeline and a markdown diff you can paste straight into a pull
request. The commands below write those files under ~/tmp~.

* Add the two flags to solve

~stack solve~ accepts ~--build-list-out~ and ~--stack-diff-out~. They are
independent: pass either, both, or neither.

#+begin_src bash
eb-stack stack solve \
  --easyconfigs fixtures/gromacs_2025_to_next/easyconfigs \
  --stack-policy fixtures/gromacs_2025_to_next/policies/prefer_newer.json \
  --baseline-easyconfigs fixtures/gromacs_2025_to_next/easyconfigs \
  --lock-out /tmp/emit-stack.lock.json \
  --sbom-out /tmp/emit-stack.cdx.json \
  --build-list-out /tmp/emit-build.list \
  --stack-diff-out /tmp/emit-stack.diff.md
#+end_src

~--stack-diff-out~ needs a baseline lock. Omit ~--baseline-easyconfigs~ and
the first ~--easyconfigs~ tree is that baseline. Pass ~--baseline-easystack~
to diff against what those easystacks install. A caller that can form no
baseline fails and names ~--baseline-easyconfigs~ or ~--baseline-easystack~.
There is no ~--baseline~ flag.

To diff against what a software layer already installs, pass its easystacks as
the baseline instead of an older tree:

#+begin_src bash
eb-stack stack solve \
  --easyconfigs fixtures/gromacs_2025_to_next/easyconfigs \
  --toolchain foss/2025b --root GROMACS \
  --baseline-easystack fixtures/gromacs_2025_to_next/easystacks/gromacs-2024.4.yml \
  --build-list-out /tmp/site.list \
  --build-list-excludes-baseline \
  --stack-diff-out /tmp/easystack.diff.md \
  --lock-out /tmp/easystack.lock.json
#+end_src

The baseline label is the toolchain (~foss-2025b~), the same shape as the
solved lock. ~/tmp/site.list~ contains the version-bumped modules in build
order, and leaves out what the easystack already installs:

#+begin_src text
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/OpenBLAS-0.3.27-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/OpenMPI-5.0.3-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/GROMACS-2025.0-foss-2025b.eb
#+end_src

~/tmp/easystack.diff.md~ opens with ~Baseline (`foss-2025b`) to solved (`foss-2025b`)~.
Unchanged: 2 (FFTW, Python). Version-bumped: 3 (GROMACS 2024.4 to 2025.0,
OpenBLAS 0.3.24 to 0.3.27, OpenMPI 4.1.6 to 5.0.3).

* Read the build list

#+begin_src text
cat /tmp/emit-build.list
#+end_src

One easyconfig path per line, dependencies before the packages that need
them (a topological sort over the co-selected stack, ties broken by package
name for a deterministic order):

#+begin_src text
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/FFTW-3.3.10-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/OpenBLAS-0.3.27-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/OpenMPI-5.0.3-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/Python-3.12.3-foss-2025b.eb
fixtures/gromacs_2025_to_next/easyconfigs/foss-2025b/GROMACS-2025.0-foss-2025b.eb
#+end_src

Feed this straight into a sequential build pipeline: ~xargs -n1 eb build~,
a Jenkins matrix step, or a plain shell loop.

* Read the stack diff

Every co-selected package is classified against the baseline lock as
~unchanged~, ~added~, ~removed~, or ~version-bumped~:

#+begin_src markdown

A tree baseline and an easystack baseline are both labelled with the
toolchain (`foss-2025a`, `foss-2025b`). Paste the file
body directly into a pull request description; every line names a real
version and a real easyconfig path.
